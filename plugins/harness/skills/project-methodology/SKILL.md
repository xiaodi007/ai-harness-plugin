# 项目方法论资产 · 取用路径

> 本 skill 是**指针，不是副本**。判据原文一条都不在这里 ——
> 抄过来就是「同一个事实两个写入者」，必漂，而且源仓的中立性检查管不到抄出去的那份。

## 一、资产在哪

唯一源：`$METHODOLOGY`，四个文件。下文命令都用这个变量，先设好：

```bash
METHODOLOGY="${HARNESS_METHODOLOGY_DIR:-$HOME/code/web2/keel/docs/方法论}"
```

默认值是源仓在本机的位置；换机器或源仓搬家时设 `HARNESS_METHODOLOGY_DIR`，不改本文件。

| 文件 | 答什么 |
|---|---|
| `静默失败模式目录.md` | **什么会出错**，尤其是不报错的那些：机制分类 + 门禁清单 + 三条元判据 |
| `项目记忆模型与工作流循环.md` | **知识放在哪、怎么流动**：四层记忆、固化迁移、交接卡与任务切分 |
| `AI协作协议.md` | **怎么和人一起干**：对齐与出题、范围与阶段、并行、审查态度、交付判据、数据边界 |
| `新项目指令-派生起点.md` | **派生物**：拷走它、填空位，填完它就是新项目的项目指令 |

前三份技术栈中立（有守卫在管，见 §五），第四份是给新项目填的空表。

## 二、怎么取（三步，别自创流程）

```bash
ls "$METHODOLOGY"
```

路径在 → 把**整个目录**拷进新仓。四个文件必须待在同一个目录里，派生起点的相对链接靠这一点：

```bash
cp -r "$METHODOLOGY" <新仓>/docs/方法论
```

然后**先读 `新项目指令-派生起点.md`**，之后完全按它的 §一 走 ——
拷什么、填哪些空位、第一周先建哪几个守卫，全在那份里面，**本 skill 不复述**。

⚠️ **开工不要通读三份源**。按派生起点 §三 的分工按需查。

## 三、路径不在时（换了机器 / 仓库改名 / 目录搬过）

```bash
find ~/code -maxdepth 5 -name "新项目指令-派生起点.md" 2>/dev/null
```

找到了就用它所在的目录，并**告诉用户路径变了**，请用户设 `HARNESS_METHODOLOGY_DIR`，否则下次还得再找一遍。

**仍然找不到 → 停下来问用户，绝不自己重写一套。**
这套东西是几十轮真实事故提炼出来的。凭印象重写出来的版本看起来很像，
少掉的恰恰是那些「不报错的失败模式」—— 而少了什么，当场看不出来。

## 四、改判据往哪改

**源仓那份是唯一源，新仓那份是快照。**
在别的项目里提炼出一条新判据时：先回写源仓的方法论目录，再重新拷过去。

理由：这套资产的价值全在「同一条判据被多个项目验证过」。
各仓独立演化两轮之后就合不回来了，而合不回来就等于每个仓各有一套私货。

代价照说：新仓改判据要跨仓操作，不顺手。
**顺手的那条路（就地改）会静默产生分叉**，所以不选它。

## 五、动过方法论之后必跑

```bash
python3 "$METHODOLOGY/../../scripts/docs/check-neutrality.py"
```

（脚本自己锚定 `__file__`，从任何目录跑都行；**新仓里没有这个脚本** ——
这正是 §四 要求判据回写源仓的配套：源在哪，管它的守卫就在哪。）

两项检查：三份源里技术栈特定词必须全 0（出现即说明那段内容其实属于项目指令，分层错了）；
相对链接不许出本目录（否则拷到新仓当场断链，而**没人会在新仓跑源仓的检查**）。
负向验证走 `--self-test`。
