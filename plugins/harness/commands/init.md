按方法论 v1 §5「阶段 −1 接入 / 阶段 0 立项」执行。方法论源在 `${HARNESS_METHODOLOGY_DIR:-~/code/web2/ai-use}`，只在需要时按节查阅，不要整份读进来。

1. 预演：运行 `node "${CLAUDE_PLUGIN_ROOT}/scripts/init.mjs" --dry-run $ARGUMENTS`，把「将新建 / 已有 / 建议」原样告诉维护者。判断是**新仓**（几乎没有代码和文档）还是**存量仓**。
2. 落盘：维护者同意后，去掉 `--dry-run` 再跑一次。脚本只新建缺的文件，已有文件一个字节都不改。
3. 存量仓，起草项目指令：
   - 读现有的 DECISIONS、README、docs 下的方案文档、会话记忆（`~/.claude/projects/<本仓路径转义>/memory/`），按需读，不要全量。
   - 在生成的 `AGENTS.md` 模板里只填 `<!-- 填：… -->` 空位：本项目的事实源、外发规则、红线（每条附一句来源事故）。其余内容保持模板原样。不得超过 200 行。
   - 起草稿**先给维护者看**，审定后再写盘。已有的 CLAUDE.md 不改，只按脚本建议提醒维护者自己决定要不要加 `@AGENTS.md`。
   - 脚本报的熵超预算（例如 DECISIONS 过大）只提建议，不自动归档。
4. 新仓，走立项对话：
   - 请维护者口述 `PROJECT.md` 各项。
   - 用大白话复述，列出会改变方案的模糊点（不超过 7 个），给推荐和代价。
   - 答完后写进 `PROJECT.md`，把定下的方向记成 `DECISIONS.md` 第一条。
5. 存量仓还要接着做两件事，每件都先给维护者看：
   - 用 `/harness:map` 起草系统地图；
   - 用 `/harness:invariants` 起草 10～20 条不变量，并记录基线。
6. 收尾：列出新建了哪些文件，以及还空着、需要维护者补的位置。不提交，提交由维护者决定。
