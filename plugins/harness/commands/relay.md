description: 核对收口条件，更新任务卡交接节并生成下一会话开场 prompt
argument-hint: <任务卡路径>
---

按方法论《项目记忆模型与工作流循环》§四「交接卡」执行，任务卡路径为 `$ARGUMENTS`。

1. 先判是调度还是接力：调度是把大任务切小，结果要回到本会话，由本会话开子会话；接力是本段收口、旧会话结束。本命令只管接力。若是调度，说明不适用并停止。接力时**只写卡和开场 prompt，不开新会话**，由维护者自己开，避免关联会话把旧会话叫醒。
2. 核对收口点：本单元结论已写进卡；账本无本线在跑的活；议程已更新。运行 `node "${CLAUDE_PLUGIN_ROOT}/scripts/session-start.mjs" --ledger-only` 查看账本，结合任务卡判断所属工作线；读取失败、账本不存在或截断而无法核实，不视为无活，需说明证据不足。另外，若本卡状态已是 `done`，运行 `node "${CLAUDE_PLUGIN_ROOT}/scripts/card-check.mjs" $ARGUMENTS`，必须通过（或卡里写了「校验豁免：理由」）。任一条件不满足，停下说明缺哪条。
3. 在任务卡的「交接」节就地重写，不追加第二个交接节；没有该节时创建一个。先核实 HEAD 与未推送状态（没有 git 或没有上游时如实注明），再写齐：HEAD 与未推送状态、本段做了、在跑的活、下一步、别重做、等你（交接节里一件一行「等你：…」，答完的删掉；没有写「等你：无」；本段新拿到的维护者结论写成「维护者定（MM-DD）：…」行）。不要凭记忆猜测仓库状态。
4. 最后给一段不超过 15 行的开场 prompt，包含卡路径、读哪几节、下一步、别重做、待拍板；不复述对话内容。
